# Counter-Fraud Framework

### [[Counter-Fraud Maturity Model]] — `references` [EXTRACTED]
- **What this link tells you:** When assessing whether a Member Organisation is compliant with the SAMA Counter-Fraud Framework, don't treat control existence as a pass/fail — the Framework measures compliance against the Counter-Fraud Maturity Model, which grades six cumulative levels (0–5) and requires all criteria of preceding levels before a higher level can be claimed. The Framework defines the model as its measurement instrument, so a supervisory self-assessment answer is only meaningful when expressed as a maturity level. You would conclude that reaching levels 3+ (formalised, embedded controls) is the practical compliance benchmark, and that partial or informal controls score at level 1–2 regardless of good intentions.

### [[Cyber Security Framework]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping a Member Organisation's counter-fraud obligations, do not treat the Counter-Fraud Framework as self-contained — it expressly directs that it 'should be implemented in conjunction with' SAMA's Cyber Security Framework for cyber-specific requirements, and mandates operational alignment of Counter-Fraud, Cyber Security and Financial Crime teams. This means compliance is assessed against both frameworks jointly where fraud and cyber controls overlap. Conclude that you must cross-reference the Cyber Security Framework for the cyber-related control detail and align the two regimes rather than satisfying counter-fraud requirements alone.

### [[Detect Domain]] — `references` [EXTRACTED]
- **What this link tells you:** When mapping which control requirements bind a Member Organisation, recognise that 'Detect' is one of the four mandated domains structuring the Counter-Fraud Framework, carrying its own Principle and Control Requirements. ### [[Governance Domain]] — `references` [EXTRACTED]
- **What this link tells you:** When assigning accountability for a counter-fraud programme, note the Governance domain is the framework component that fixes where responsibility sits: the Board and Executive Leadership are ultimately responsible, and organisations must establish a Counter-Fraud Governance Committee headed by an Executive Committee member with defined membership. Because Governance is a mandated domain with its own Principle and Control Requirements, these are enforceable structural obligations. Conclude that board/senior-management ownership and the CFGC composition requirements must be evidenced, and check the Governance domain rather than treating fraud oversight as delegable operational detail.

### [[Prevent Domain]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping which controls a Member Organisation must implement under the Counter-Fraud Framework, treat the Prevent domain as one of four mandated structural pillars (Governance, Prevent, Detect, Respond), each carrying its own Principle and Control Requirements. Prevent covers proactive, risk-based controls — segregation of duties, authentication, due diligence, transaction limits, underwriting — that must be documented in fraud prevention standards, periodically reviewed, and calibrated to the Fraud Risk Assessment and Fraud Risk Appetite. You would conclude that preventive controls are not discretionary add-ons but a required domain whose adequacy is judged against the organisation's own risk assessment output.

### [[Respond Domain]] — `references` [EXTRACTED]
- **What this link tells you:** When evaluating a Member Organisation's fraud incident-handling obligations, the Respond domain is the mandated fourth pillar of the Framework and requires a defined, approved and maintained Fraud Response Plan, not merely ad hoc handling. The Plan must set out alerting channels for customers/employees/third parties, roles, escalation and decision-making authority, and require prompt assessment, investigation and resolution plus root-cause review. You would conclude that absence of a formal, monitored Fraud Response Plan is a direct compliance gap against a required domain, distinct from prevention/detection obligations.
- **Grounding — this node (Page 9):** "The Framework is structured around four main domains, namely: Governance, Prevent, Detect, Respond"
- **Grounding — related node (Page 51 / 6.1):** "Member Organisations should define, approve, implement and maintain a Fraud Response Plan to outline the organisational response to an actual or suspected fraud incident."
