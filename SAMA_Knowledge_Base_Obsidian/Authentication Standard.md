# Authentication Standard

## Connections

### [[Cyber Security Framework]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping authentication obligations under the Counter-Fraud Framework, do not treat them as self-contained: the Framework expressly directs Member Organisations, when defining their authentication standard, to apply specific Cyber Security Framework control requirements (3.3.5 Identity and access management; 3.3.13 Electronic Banking Services). Because the Counter-Fraud Framework states it 'should be implemented in conjunction with' SAMA's Cyber Security Framework for cyber-specific requirements, compliance with the authentication principle is only demonstrable by cross-checking against those named CSF controls. Conclude that an authentication standard must satisfy both instruments jointly, with input from both the Counter-Fraud Department and Cyber Security Team, and cannot be assessed against the fraud text alone.
- **Grounding — this node (Page 37 / 4.4 Authentication):** "Member Organisations should take note of the following Control Requirements outlined in The Cyber Security Framework: 3.3.5 Identity and access management; 3.3.13 Electronic Banking Services"
- **Grounding — related node (Page 7 / 1.3 Scope):** "The Framework should be implemented in conjunction with other SAMA frameworks, in particular SAMA's Cyber Security Framework ... which should be referred to for specific Cyber Security related requirements."

### [[Prevent Domain]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping fraud-prevention obligations, treat the Authentication Standard (sub-domain 4.4) as a mandated Prevent-domain control, so authentication weaknesses are assessed as prevention-control failures under the Framework. The Prevent domain requires proactive controls to stop fraud before harm, and expressly cites authentication among the systems and technology implemented to prevent fraud; the standard must be risk-based, use multi-factor authentication, and be built jointly by Counter-Fraud and Cyber Security with reference to the Cyber Security Framework's identity/access and electronic-banking controls. A reviewer should confirm the authentication standard covers customers, employees and third parties across digital and non-digital channels and is calibrated to the Fraud Risk Assessment — cross-checking the referenced Cyber Security Framework controls (3.3.5, 3.3.13) rather than relying on Prevent-domain text alone.
- **Grounding — this node (Page 37 / sub-domain 4.4 Authentication):** "Member Organisations should define, approve, implement and maintain a standard for the authentication of customer, employee and third party credentials ... This should be risk-based and utilise multi-factor authentication."
- **Grounding — related node (Page 40 / Section 4 Prevent):** "Systems and technology implemented to prevent fraud (e.g., identity and access management, authentication, issuance of one-time-passwords, biometrics)."
