# SAMA Cyber Security Framework

## Connections

### [[Cyber Security Leadership and Governance]] — `references` [EXTRACTED]
- **What this link tells you:** When mapping accountability for cyber security in a SAMA Member Organization, start from the Framework's governance domain because it fixes where ultimate responsibility sits — the Board of Directors — and requires the cyber security policy to define general and specific responsibilities. This is a defining/structural link: 'Leadership and Governance' is the Framework subdomain that assigns board intent, roles, and senior-management/CISO duties. Conclude that governance obligations (board sign-off, defined roles, policy content) are directly assessable Framework requirements you can hold the entity to, not aspirational best practice.
- **Grounding — this node (Page 15, §3.1.4):** "The Board of Directors has the ultimate responsibility for cyber security"
- **Grounding — related node (Page 15, §3.1.4 Cyber Security Roles and Responsibilities):** "Responsibilities to implement, maintain, support and promote cyber security should be defined throughout the Member Organization"

### [[Cyber Security Maturity Model]] — `references` [EXTRACTED]
- **What this link tells you:** When assessing or self-assessing compliance with the Cyber Security Framework, use the Maturity Model as the measurement scale SAMA applies — it defines six levels (0–5) and requires that all criteria of preceding levels be met before a higher level is achieved. This link tells you the Framework's controls are graded, not simply pass/fail, so a control that is 'repeatable but informal' (level 2) is not the same as 'defined, approved and implemented' (level 3). Conclude that any gap analysis must map each control to a maturity level and cannot claim a target level without satisfying every lower-level criterion.
- **Grounding — this node (Page 10, §2.4):** "The cyber security maturity level will be measured with the help of a predefined cyber security maturity model"
- **Grounding — related node (Page 10, §2.4):** "In order to achieve levels 3, 4 or 5, a Member Organization must first meet all criteria of the preceding maturity levels"

### [[Cyber Security Operations and Technology]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping which cyber security controls apply to a Member Organization's systems and delivery channels, treat 'Operations and Technology' as one of the Framework's substantive control domains that sits under the same governance and risk-treatment structure, so operational/technical controls must still trace back to defined ownership, documented risk treatment, and board-level accountability. The Framework binds risk acceptance to business-owner sign-off and prohibits accepting risks that contradict SAMA regulations, meaning technology controls cannot be waived on operational convenience alone. Conclude that operational/technology control deficiencies should be evaluated as Framework non-compliance with a required risk-treatment and approval trail.
- **Grounding — this node (Page 21):** "the accepted cyber security risk does not contradict SAMA regulations"
- **Grounding — related node (Page 21 (risk response/treatment control considerations)):** "accepting, avoiding, transferring or mitigating risks by applying cyber security controls"
- **Caveat:** The provided context does not include the full text of the Operations and Technology subdomain; its scope is inferred from the Framework's shared governance/risk-treatment structure — confirm specific controls against the relevant Framework section.

### [[Cyber Security Risk Management and Compliance]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping a Member Organization's obligations under the SAMA Cyber Security Framework, treat the risk-management-and-compliance domain as a mandatory, enforceable component of the Framework itself, not an optional add-on. The Framework (Section 3.2) requires that a cyber security risk management process be defined, approved and implemented, aligned with enterprise risk management, and that compliance with cyber security controls be subject to periodic review and audit; accepted risks must not contradict SAMA regulations. Conclude that Framework maturity assessments and audits will test whether the risk identification/analysis/response/monitoring cycle exists and whether residual-risk acceptance stays inside approved limits and SAMA rules.
- **Grounding — this node (Page 21 / Control considerations):** "the accepted cyber security risk does not contradict SAMA regulations."
- **Grounding — related node (Page 19 / 3.2):** "The compliance with the cyber security controls should be subject to periodic review and audit."

### [[SAMA (Saudi Arabian Monetary Authority)]] — `references` [EXTRACTED]
- **What this link tells you:** When determining who this Framework binds and who enforces it, note that SAMA is both issuer and supervisor: the Framework applies to SAMA-regulated Banking, Insurance and Financing Companies sectors, and any deviation runs through SAMA (via the Deputyship of Supervision / IT Risk Supervision). Update and waiver requests are submitted to the deputy governor of SAMA IT Risk Supervision, meaning MOs cannot self-authorize exemptions from controls. Conclude that non-compliance is a supervisory matter and that departures from Framework controls require SAMA's formal waiver process, not internal sign-off alone.
- **Grounding — this node (Page 44 / Appendix E):** "Request for Waiver from the SAMA Cyber Security Framework — A submission to the deputy governor of SAMA IT Risk Supervision"
- **Grounding — related node (Page 2 / Foreword):** "Saudi Arabian Banking, Insurance and Financing Companies sectors can manage and withstand cyber security threats."

### [[Third Party Cyber Security]] — `references` [EXTRACTED]
- **What this link tells you:** When assessing a Member Organization's exposure, do not stop at its own systems: the Framework extends cyber security obligations to third-party service providers, so vendor arrangements fall within the same compliance perimeter. The Framework requires that providers used for disposal, transport and storage comply with the applicable standards and that their effectiveness be periodically measured, and it mandates compliance with contractual obligations. Conclude that outsourcing does not transfer the MO's accountability; supervisory review will look at whether third-party controls meet Framework standards.
- **Grounding — this node (Page 15 / 4.f):** "compliance with regulatory and contractual obligations are being met;"
- **Grounding — related node (Page 31):** "third party service providers ... comply with the secure disposal standard and procedure and the effectiveness is periodically measured and evaluated."
