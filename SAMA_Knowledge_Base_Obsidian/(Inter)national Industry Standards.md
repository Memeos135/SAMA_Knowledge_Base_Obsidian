# (Inter)national Industry Standards

## Connections

### [[Cyber Security Risk Management and Compliance]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping compliance obligations, treat mandatory (inter)national industry standards (3.2.3) as a discrete enforceable requirement sitting inside the Risk Management and Compliance domain (3.2), not as optional best practice. The framework states the Member Organization 'should comply with' PCI-DSS, EMV, and the SWIFT Customer Security Controls Framework, and these obligations are audited under the domain's periodic review-and-audit regime. A reviewer should confirm applicability of each named standard to the organization's activities (e.g. card and payment operations) and conclude that non-compliance is a compliance-domain breach regardless of general risk posture.
- **Grounding — this node (Page 22 / 3.2.3):** "The Member Organization should comply with: a. Payment Card Industry Data Security Standard (PCI-DSS); b. EMV ...; c. SWIFT Customer Security Controls Framework"
- **Grounding — related node (Page 19 / 3.2):** "The compliance with the cyber security controls should be subject to periodic review and audit."

### [[PCI-DSS Standard]] — `references` [EXTRACTED]
- **What this link tells you:** When assessing a Member Organization's compliance obligations, treat PCI-DSS as a mandatory, incorporated requirement of the SAMA Framework — not an optional best practice. Section 3.2.3 states the organization 'should comply with mandatory (inter)national industry standards' and expressly lists 'Payment Card Industry Data Security Standard (PCI-DSS)' among the standards with which it must comply. For any entity handling payment card data, conclude that PCI-DSS conformity is a distinct compliance item enforceable via the Framework, so gaps against PCI-DSS are also Framework non-compliance.
- **Grounding — this node (Page 22 / 3.2.3):** "The Member Organization should comply with mandatory (inter)national industry standards."
- **Grounding — related node (Page 22 / 3.2.3 control 1):** "The Member Organization should comply with: a. Payment Card Industry Data Security Standard (PCI-DSS)"

### [[SWIFT Customer Security Controls Framework]] — `references` [EXTRACTED]
- **What this link tells you:** When scoping which external standards a Member Organization must meet, include the SWIFT Customer Security Controls Framework as a named mandatory standard under the SAMA Framework alongside PCI-DSS and EMV. Section 3.2.3 requires compliance with mandatory standards and specifically lists 'SWIFT Customer Security Controls Framework – March 2017'. For entities using SWIFT messaging, conclude that SWIFT CSCF attestation obligations are pulled into SAMA's enforceable compliance scope, so a failure there is also a Framework deficiency; verify the referenced version date remains current against SWIFT's later revisions.
- **Grounding — this node (Page 22 / 3.2.3):** "The Member Organization should comply with mandatory (inter)national industry standards."
- **Grounding — related node (Page 22 / 3.2.3 control 1):** "c. SWIFT Customer Security Controls Framework – March 2017."
